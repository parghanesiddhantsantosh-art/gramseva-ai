FOUNDATIONAL CONCEPTS

Need for I/O Interfaces & Device Interconnection

02 / 07
The Peripheral Mismatch Problem
  • Speed Disparity: CPUs operate at GHz frequencies, while disk drives, keyboards, and network adapters are orders of magnitude slower.
  • Data Formats: Peripherals often stream serial bits, whereas system buses transfer 32-bit or 64-bit parallel words.
  • Clock Domains: External devices operate on independent asynchronous clocks relative to the CPU system clock.
Core I/O Interface Registers
  • Data Bus Buffer: Holds data words temporarily during speed matching between the system bus and device.
  • Status Register: Houses condition flags (Busy, Ready, Error, Parity) for CPU status queries.
  • Control Register: Stores functional operation commands issued by the CPU (Read, Write, Seek).
  • Address Decoder: Detects the unique device port address on the bus.
Notes "Peripherals cannot be connected directly to system buses. An I/O Interface acts as a hardware bridge that buffers speed differences, translates serial to parallel signals, and decodes addresses so the CPU can communicate reliably."
TRANSFER METHOD 1

Program-Controlled I/O (Polling)

03 / 07
Execution Cycle (Busy-Waiting)
1 CPU writes command word to interface Control Register.
2 Interface sets Busy bit; device begins physical access.
3 Polling Loop: CPU repeatedly reads Status Register in a tight loop.
4 Device places byte in buffer and flags Ready.
5 CPU reads byte into register, then stores it to RAM.
Major Engineering Drawbacks
  • Extreme CPU Wastage: High-performance cores waste millions of clock cycles executing empty test-and-branch instructions.
  • Zero Multitasking: Operating system threads and background calculations remain completely blocked.
  • Unpredictable Latency: Transfer time fluctuates with mechanical device readiness.
  • Application: Restricted to simple microcontrollers or dedicated single-task boot routines.
Notes "Programmed I/O holds the CPU hostage in a busy-waiting loop. It repeatedly checks if the device is ready, wasting over 95% of processor clock cycles on slow peripherals."
TRANSFER METHOD 2

Interrupt-Driven I/O & Classification

04 / 07
Interrupt Servicing Cycle
  • Asynchronous Initiation: CPU issues command and immediately resumes user program execution.
  • INTR Assertion: Peripheral raises an Interrupt Request (INTR) when ready.
  • Context Preservation: CPU completes current instruction, pushes Program Counter (PC) and Flags (PSW) to the stack.
  • ISR Execution: Vector table branches to Interrupt Service Routine to read/write the byte.
  • IRET Return: Context is popped and execution resumes seamlessly.
Interrupt Types & Privileges
  • Hardware Interrupts: Asynchronous electrical signals triggered on external CPU pins (e.g., keyboard keystrokes, disk heads).
  • Software Interrupts (Traps): Synchronous exceptions or system calls (e.g., INT 21h, SYSCALL) requesting OS kernel routines.
  • Privileged Instructions: Direct I/O instructions (IN, OUT) are restricted to Kernel Mode to protect hardware from user corruption.
Notes "Interrupts free the processor from polling. The CPU does useful work until the hardware signals an INTR pin. The CPU saves its registers on the stack, runs the ISR, and pops back to user code."
ARCHITECTURAL BOTTLENECK

Why Interrupts Fail for Bulk Data Transfers

05 / 07
Peripheral Device
➔
I/O Interface
➔
CPU Accumulator (Bottleneck)
➔
Main Memory (RAM)
Context-Switching Overhead
  • Per-Byte Overhead: Pushing registers, acquiring vector address, executing ISR instructions, and popping context takes 30–80+ clock cycles per byte.
  • Interrupt Saturation: Transferring a 4 KB disk sector byte-by-byte generates 4,096 consecutive interrupts, flooding the CPU pipeline completely.
The Solution: Direct Memory Access (DMA)
  • Hardware Bypass: DMA offloads data movement to a dedicated coprocessor that controls system buses directly.
  • Zero CPU Routing: Data moves directly between I/O and RAM with zero CPU register involvement during block streaming.
Notes "While interrupts work well for a single keystroke, routing a multi-megabyte file byte-by-byte through CPU registers creates extreme context-switch overhead. DMA eliminates this by providing a direct hardware highway between device and RAM."
DMA ARCHITECTURE & OPERATION

DMA Controller Internal Architecture & Handshake

06 / 07
Internal Register Components
  • Memory Address Register (MAR): Holds the physical target RAM address; auto-increments after every word transferred.
  • Word Count Register (WCR): Stores total words in the block; auto-decrements until reaching zero (Terminal Count).
  • Control Register: Configures transfer direction (Memory-to-I/O or I/O-to-Memory) and transfer mode.
  • Status Register: Holds status flags (Active, TC reached, Error).
Bus Handshake & Arbitration
  • HOLD (Bus Request): DMA asserts HOLD to request mastership of address, data, and control lines from CPU.
  • HLDA (Hold Acknowledge): CPU completes current bus machine cycle, places system bus pins into high-impedance (tri-state), and grants control.
  • Transfer Execution: DMAC places addresses directly on bus and triggers memory write/read pulses.
  • Completion IRQ: When WCR = 0, DMAC interrupts CPU once to report completion.
Notes "The DMA controller contains an address register that increments and a word count register that decrements to zero. It uses HOLD and HLDA lines to take bus control from the CPU, writes directly to memory, and raises one single interrupt when the entire block is done."
